# Privacy request runbook

Use this procedure for access, correction, deletion, portability, opt-out, and appeal requests.

## Intake

1. Record the request date, requester, state or country, requested right, affected account or wedding, and response deadline.
2. Acknowledge receipt without confirming that an email address or person exists in Phera.
3. Assign one accountable owner.

## Verification

1. Use information already held by Phera where practical.
2. Do not request more sensitive information than needed.
3. For a guest record controlled by a couple, verify the guest and notify or route the request to the account owner unless law requires Phera to act directly.
4. Verify an authorized agent’s authority.

## Search

Check:

- Firebase Authentication
- `users`
- Private and public wedding projections
- Guests and public guest directory
- Events, RSVP responses, seating, photo groups, game votes, collaborators, and settings
- Support, security, legal, and copyright mailboxes
- Backups and logs, subject to documented retention exceptions

## Response

1. Export in a readable format when required.
2. Correct records in both private and public projections.
3. Delete or de-identify records unless a documented legal, security, fraud, or dispute exception applies.
4. Record systems changed, exceptions, approver, completion date, and response sent.
5. Explain any denial and the appeal method.

## Operational rules

- Never send one person another guest’s information.
- Remove the requester from public pages promptly while verification continues when risk is clear.
- Preserve only the minimum record needed to prove the request was handled.
- Have counsel set jurisdiction-specific response periods and extension rules.
